What's attached, and which script runs

The router the assistant uses in chat to pick a mode (A–H), the exact Python entry point each one calls, and the scripts that live outside the router entirely — run on a schedule, or by hand, once a statement's already logged. Source: README.md §Workflow Modes, binding per CLAUDE.md.

Every A / C / E / G run ends the same way

One confirmation gate per statement

applies to modes A · C · E · G — never to B, D, F, H

print report, verbatim → "Entered in QuickBooks?"
DONE
  • log status DONE / CLEAN
  • archive PDF to Google Drive
  • sync the tracker sheet
LATER
  • log status IN_PROGRESS
  • stop — wait for mark_clean.py

Never auto-advances to the next statement — one at a time, earliest date first; credit cards before the checking statements that pay them.

Mode reference

8 modes · A–H
A

Reconciliation

QB gate

script

python3 reconcile_comprehensive.py <statement.pdf> \
  [output.txt] [--dry-run] [--no-prompt]
  [--check-payee 1235='Jane Doe']

Parses the PDF, prints balances / charges / payments / checks, runs the balance check, reads back client notes.

B

Payroll Journal Entry

logged, no QB gate

script

python3 payroll.py <client_key> <pdf> \
  [--config client.json] [--pay-by-pay AMOUNT]

Prints the journal entry (Agency, then Admin — confirmed separately for Labor Distribution clients) and logs to payroll_log.csv.

C

Payroll + Tie-Out

QB gate

script

python3 reconcile_comprehensive.py <checking.pdf>
# cross-checks payroll_log.csv — no separate binary

Confirms a payroll disbursement (this session's Mode B, or a prior logged run) matches a checking debit to the penny.

D

QA Verification

no QB gate — this is the QB check

script

python3 qa_reconciliation.py <statement.pdf> <qb_data.json>
python3 qa_reconciliation.py <statement.pdf> --json '{...}'

Diffs a JSON snapshot (built from QB Reconcile screenshots) against the statement — catches missing, duplicate, mismatched entries.

E

CC Payment Tie-Out

QB gate

script

python3 reconcile_comprehensive.py <checking.pdf>
# cross-checks recon_log.json — no separate binary

Confirms a checking-side CC payment debit matches the payment already logged on the credit card statement.

F

Add New Client

walkthrough, no single script

touches, in order

clients/<key>.json
sheets_config.json      # cell map
digest_config.json      # tracker entry
reconcile_comprehensive.py  # test run

Onboards config first, then proves it with a real reconciliation and a digest check.

G

Manual Entry

QB gate

script

manual_statements.json  # hand-edited first
python3 manual_statement_entry.py [--month MM-YYYY]

For scanned/unparseable PDFs — same report / QB-confirm / sync flow as Mode A, values entered by hand.

H

Upload Test Fixture

no QB gate

script

python3 upload_fixtures_to_drive.py \
  <entry_name> <format> <pdf_path>
python3 upload_fixtures_to_drive.py --migrate-repo

Archives a reconciled statement as a fixture, records it in fixtures_manifest.json, so future parser changes have real data to test against.

Outside the router

scheduled or run by hand — not mode-selected
script when does
mark_clean.py <client> <acct> [date] QB entry confirmed after the fact Finds the matching IN_PROGRESS entry, marks it DONE, updates the CSV, sheet, and pushes.
mark_payroll_done.py <key> <date> <amount> payroll bank credit confirmed later Same idea as mark_clean.py, for payroll_log.csv.
send_morning_digest.py [--date] [--scheduled] [--cc-due] every morning, cron-triggered Builds and sends the color-coded tracker digest by Gmail SMTP — what ran, what's pending, what's blocked.
drive_archiver.py [--dry-run] <pdf> <client> <acct> [date] called internally by Mode A/C/E/G on DONE Uploads to Bookkeeping/<Client>/<Account>/, dedupes by filename, keeps the 2 most recent.
tools/pii_scan.py [--staged | --audit] pre-commit hook, and before any publish Flags real names / account numbers not in pii_allowlist.txt before code reaches the public repo.
tools/backfill_status.py <old> <new> a status string gets renamed in code Rewrites matching values across the private logs dir so history stays consistent with the new name.
tools/dedup_recon_log.py [--apply] log hygiene, run by hand Dry-run by default — shows duplicate recon_log.json entries before removing them.
alert_failure.py [subject] GitHub Actions sync_tracker workflow fails Emails a failure alert — sender/recipient come from env, never hard-coded.
